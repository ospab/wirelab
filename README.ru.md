# wirelab

Стенд для проверки цензуроустойчивых транспортных протоколов. Лаборатория
состоит из трёх зон: клиент, сервер и провод между ними. Клиент и сервер
вы запускаете свои; провод пропускает их трафик через помехи канала и
модель цензора и показывает то, что видит наблюдатель на пути.

[English version](README.md)

## Что внутри

- **Лаборатория** (`wirelab lab`): клиент, провод и сервер в контейнерах,
  плюс цель, которая изображает интернет за сервером. Локальная панель даёт
  консоль в клиенте и в сервере, живой захват пакетов, помехи канала
  (netem) и управление цензором.
- **Цензор** (`wl-censor`): маршрутизирует лабораторию и применяет пресет
  поведения цензора. У каждого правила указана статья или отчёт, который
  оно воспроизводит; то, чего источники не решают, оформлено как именованная
  гипотеза, которую можно включить или выключить. Тот же движок проверяет
  любой файл pcap или pcapng.
- **Симулятор** (`wirelab run`): обе стороны в одном процессе поверх
  симулированного канала, для протоколов с sans-io ядром. Пока есть один
  адаптер, OSTP.

Исходы: `PASS`, `FAIL` или `NO DATA`. Проверка, которая не смогла
измерить, так и говорит; за успех она не считается никогда.

## Что нужно

- Rust (stable) и Go 1.26 или новее.
- Docker Engine на Linux или внутри WSL2 на Windows. На Windows
  лаборатория по умолчанию обращается к дистрибутиву `Debian`; другой
  задаётся через `WIRELAB_WSL_DISTRO`.
- Для адаптера OSTP в симуляторе — checkout `ostp` рядом (`../ostp`).

## Запуск лаборатории

```
cargo build --release
cd wirelab-censor && GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o ../containers/wire/bin/wl-censor . && cd ..
./target/release/wirelab lab up
./target/release/wirelab lab panel
```

`lab up` печатает адреса: сервер — `10.77.2.3`, слушает порт 443, если не
указан `--port`; клиент подключается к нему по этому адресу. Папка
`lab/<id>/<узел>/` — это `/lab` внутри контейнера, и `/lab/setup.sh`
оттуда выполняется при каждом старте узла, так что лабораторию можно
пересоздать, не настраивая всё заново руками.

`lab panel` печатает ссылку с токеном, созданным для этого запуска. Откройте её, выберите
**Russia (TSPU)** в разделе Censor, примените и запустите сервер и клиент
в двух консолях. Каждое решение цензора появляется в панели с правилом и
его источником и пишется в папку сессии вместе с захватом и обеими
консолями.

## Проверка записи

```
cd wirelab-censor && go build -o ../target/wl-censor . && cd ..
./target/wl-censor -replay session.pcap -preset containers/censor/presets/ru-tspu.json \
    -client-net 192.168.1.0/24 -server-net 203.0.113.7/32
```

В отчёте по каждому правилу перечислены потоки, которые оно заблокировало
бы, и на каком пакете. Правила, написанные под адреса лаборатории,
переносятся на переданные сети.

## Как дополнять пресеты

Пресеты лежат в `containers/censor/presets/`. Правило без `source` не
загрузится. Если источники не решают, как ведёт себя цензор, добавьте
гипотезу, а не выбирайте ответ молча.

## Устройство

| Путь | Что |
|---|---|
| `wirelab-cli/` | команда `wirelab` |
| `wirelab-lab/` | управление лабораторией и панель |
| `wirelab-censor/` | цензор (Go): режим маршрутизатора и `-replay` |
| `wirelab-wire/`, `wirelab-sim/`, `wirelab-core/`, `wirelab-ostp/` | симулятор |
| `containers/` | файлы узлов, провода и цензора, подключаемые в лабораторию |
| `docs/` | план и отчёты |
