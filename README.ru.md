**Стенд для проверки цензуроустойчивых транспортных протоколов.** Клиент, сервер и провод между ними. Провод пропускает их трафик через помехи канала и модель настоящего цензора и показывает, что видит наблюдатель на пути. Работать можно руками из панели в браузере, а можно отдать стенду целую матрицу протоколов, версий, цензоров и условий сети и получить таблицу PASS, FAIL и NO DATA.

Всё работает на вашей машине, в Docker: без минут CI, без VPS, сколько угодно прогонов.

## Что внутри

- **Лаборатория.** Клиент, провод, сервер и сайт за сервером в контейнерах в изолированных сетях. Локальная панель: консоли в клиенте и сервере, живой захват с разбором рукопожатий, графики скорости и RTT, помехи канала (netem) и управление цензором. Сессия упаковывается в один архив.
- **Рецепты.** OSTP (UDP, UoT, TLS), VLESS-REALITY (Xray), Shadowsocks и WireGuard настраиваются на обеих сторонах одной командой, из релиза или из вашей сборки.
- **Прогоны.** `wirelab lab test scenario.toml` перебирает рецепты × версии × цензоры × каналы, на каждую клетку свежая лаборатория. Нагрузки: передачи со сверкой sha256, веб-страница, ровный поток, мессенджер, простой, пробы. Плюс обрывы, медленный сайт, предел памяти сервера и сравнение версий A/B.
- **Цензор.** `wl-censor` маршрутизирует лабораторию и применяет пресет. *Russia (TSPU)* на 2026-10: блокировка по SNI, QUIC по SNI, заморозка зарубежных ДЦ, эвристики TLS-в-TLS и частоты TLS-соединений, подмена UDP DNS и другое, у каждого правила указан источник. То, чего источники не решают, вынесено в переключаемые гипотезы. Протоколы распознаёт [nDPI](https://github.com/ntop/nDPI). Тот же цензор разбирает любой pcap и pcapng.
- **Исходы CRTS.** Прогоны пишут таблицы соответствия [CRTS](https://github.com/ospab/crts): усиление, мода длин и периодичность по захватам.
- **Симулятор.** `wirelab run` помещает обе стороны sans-io-протокола в один процесс поверх модели канала с сидом.

## Быстрый старт

Нужны Docker (на Windows — внутри WSL2), Rust и git; подробно — в [Начале работы](docs/ru/getting-started.md).

```bash
git clone https://github.com/ospab/wirelab && cd wirelab
cargo build --release
./target/release/wirelab doctor                 # проверит машину и скажет, как исправить недостающее
./target/release/wirelab censor build           # цензор с nDPI, собирается в Docker
./target/release/wirelab lab up --recipe ostp --set transport=tls
./target/release/wirelab lab panel              # откройте напечатанную ссылку
```

Или пусть проверяет сам:

```bash
./target/release/wirelab lab test scenarios/lab/recipes.toml
```

## Чем это не является

Лаборатория — не цензурируемая сеть. PASS под пресетом значит «проходит эту модель цензора», а модель хороша ровно настолько, насколько хороши опубликованные наблюдения, из которых она собрана: списки имён и адресов — примеры, а часть порогов выбрана самим пресетом (он говорит, какие). Полевые результаты дают полевые тесты; пресеты нужно сверять с ними и исправлять.

## Устройство

| Путь | Что |
|---|---|
| `wirelab-cli/` | команда `wirelab` |
| `wirelab-lab/` | лаборатория, панель, рецепты, прогоны, экспорт CRTS, doctor |
| `wirelab-censor/` | цензор (Go): маршрутизатор, правила, привязка к nDPI, `-replay` |
| `wirelab-wire/` | разбор захвата, анализ, pcapng |
| `wirelab-sim/`, `wirelab-core/`, `wirelab-ostp/` | симулятор и адаптер OSTP |
| `containers/` | файлы узлов, провода и сборки цензора; пресеты цензора |
| `recipes/`, `scenarios/` | рецепты протоколов; сценарии прогонов и симулятора |
| `docs/` | документация, план, отчёты |
