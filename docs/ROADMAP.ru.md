# План

[English](ROADMAP.md)

## Сделано

- **Симулятор.** Две стороны в одном процессе поверх канала с сидом
  (задержка, джиттер с сохранением порядка, явный реордер, потери, дубли,
  битфлипы, полоса с очередью, MTU); запись, экспорт в pcapng, отчёт.
  Адаптер OSTP поверх настоящего `ostp-core`.
- **Лаборатория.** Контейнеры клиента, провода, сервера и цели в
  изолированных сетях; `/lab/setup.sh` на каждом узле; базы Alpine или
  Debian; порт сервера задаётся при `lab up`.
- **Панель.** Консоли в клиенте и сервере, живой захват с разбором
  ClientHello и ICMP, netem на весь путь (задержка RTT делится между
  направлениями), поиск секретов в открытом виде, колонки с изменяемой
  шириной, всё пишется в папку сессии.
- **Цензор.** Программный маршрутизатор в проводе с журналом решений.
  Пресет Russia (TSPU): SNI-I, SNI-II, SNI-IV, QUIC v1, IP, WireGuard,
  OpenVPN, заморозка для зарубежных дата-центров; у каждого правила указан
  источник. Гипотеза о сборке ClientHello переключается. IP-фрагменты
  относятся к своему потоку.
- **Проверка записей.** `wl-censor -replay` разбирает файлы pcap и pcapng.
- **Doctor.** `wirelab doctor` проверяет Docker, дистрибутив WSL, netem,
  пакетные сокеты и WireGuard в ядре, свободное место там, где лежат захваты
  и данные Docker (и где лежит диск WSL), и сборку цензора; на каждую
  проблему даёт команду. NFQUEUE оказался не нужен: цензор читает кадры через
  AF_PACKET.
- **Рецепты.** `recipes/<имя>/` с манифестом, `client.sh` и `server.sh`;
  релизы скачиваются и кэшируются, вместо релиза можно подставить локальную
  сборку. OSTP (UDP, UoT, TLS), VLESS-REALITY, Shadowsocks, WireGuard.
  `wirelab lab up --recipe ... --set k=v`.
- **Нагрузки.** Скачивание и отдача со сверкой sha256 на дальней стороне,
  веб-страница, ровный поток, мессенджер, простой, неавторизованные пробы;
  обрывы, медленный сайт, предел памяти сервера.
- **Матрица тестов с A/B.** `wirelab lab test scenario.toml`: рецепт ×
  версия × цензор × канал, свежая лаборатория на каждую клетку, таблица с
  PASS / FAIL / NO DATA, версии рядом, какое правило цензора сработало и
  когда.
- **Графики в панели.** Скорость в обе стороны и RTT (пассивно по TCP, пинг
  по запросу) за пять минут, решения цензора на шкале.
- **Экспорт сессии.** `wirelab lab export` и кнопка в панели: один .tar.gz
  с захватом, решениями, консолями, изменениями провода и рецептом.
- **Решения в Wireshark.** Решения цензора комментариями к пакетам в pcapng
  экспорта и прогонов.
- **Экспорт в CRTS.** Раздел `[crts]` в сценарии пишет `crts.md` и
  `crts.json`: CT-005, CT-006 и CT-007 по захватам, остальные тесты `NO
  DATA` с причиной.

## Дальше

В порядке, в котором стенд становится полезен не только автору.

1. **Эталонные записи для пресетов.** На каждое правило — маленькая
   запись, которая должна его вызвать, и запись, которая не должна;
   прогоняются в CI через `-replay`. Ловит пресет, который тихо перестал
   срабатывать.
2. **Новые пресеты.** Китай (эвристика полностью зашифрованного трафика
   GFW, Wu et al., USENIX Security 2023), Иран. Правило то же: источник у
   каждого правила, гипотезы для остального.
3. **Профили канала из замеров.** Настройки netem, полученные из реальных
   замеров пути (например, прогонов `ostp-prober`), с указанием, где и
   когда они сняты.
4. **Больше CRTS.** CT-001 (равномерность байтов) и CT-003 (разброс
   рукопожатий) требуют многих развёртываний с разными ключами: матрица,
   которая повторяет клетку со свежими ключами и сводит захваты вместе.
5. **CI и релизы.** Тесты Rust и Go на каждый push; релизные сборки
   `wirelab` и `wl-censor`.
