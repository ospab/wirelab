[English](ROADMAP.md)

## Сделано: in-process режим

- `wirelab-core`: зоны, симулированное время, контракт адаптера (`Endpoint`),
  запись прогона, исходы `PASS` / `FAIL` / `NO DATA`.
- `wirelab-wire`: модель канала (задержка, джиттер с сохранением порядка,
  явный реордер, потери, дубли, битфлипы, полоса с очередью, MTU), наблюдатель,
  который получает только байты и время, экспорт в pcapng.
- `wirelab-sim`: событийный симулятор, сценарии в TOML, отчёт.
- `wirelab-ostp`: адаптер настоящего `ostp-core::ProtocolMachine` с боевыми
  параметрами клиента и сервера.

Ограничение OSTP: ядро читает `Instant::now()` само, поэтому его прогоны идут
в реальном времени и по сиду воспроизводятся сбои канала, но не тайминги.

## Дальше: контейнеры

Три контейнера на Alpine в двух изолированных сетях, прямого маршрута
`client ↔ server` нет:

```
client ── net_c ── wire ── net_s ── server
```

- `wire`: `ip_forward`, `tc netem` на обоих интерфейсах (профиль из того же
  `[wire]` сценария), `tcpdump` в pcapng. Позже модели цензора на NFQUEUE.
- `client`, `server`: протокол из «рецепта» (Dockerfile + шаблоны конфигов)
  и нагрузка: `curl` через SOCKS к HTTP-цели, `iperf3`.
- `wirelab` генерирует compose-файл, запускает прогон, собирает pcap из
  `wire` и логи из зон, строит тот же отчёт.
- Рецепты: ostp, VLESS-Reality (xray), WireGuard, Shadowsocks.
- Рантайм: Docker Engine в WSL Debian.

## Потом

- Модели цензора поверх pcap (общие для обоих режимов): энтропия,
  распределения размеров и интервалов, TLS-отпечатки, активное зондирование.
  Детекторы переносятся из `ostp-prober`.
- Тесты CT-### стандарта CRTS как сценарии wirelab.
- Веб-панель с тремя колонками и общей шкалой времени (сначала `DESIGN.md`).
- Адаптер overnet.
