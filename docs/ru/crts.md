# Исходы CRTS

[English](../en/crts.md) · [Документация](../README.md)

[CRTS](https://github.com/ospab/crts), стандарт цензуроустойчивых транспортов, определяет тесты соответствия CT-001 … CT-014 с тремя исходами: `PASS`, `FAIL`, `NO DATA`. Прогон с разделом `[crts]` пишет `crts.md` и `crts.json`: таблицу исходов на каждую проверяемую реализацию (метка рецепта и версия) в формате каталога.

## Что измеряет лаборатория

| Тест | Из чего | Исход |
|---|---|---|
| CT-005 Усиление | нагрузка `unauth`: ответы на неавторизованные пробы, по захвату | отношение ответ/запрос — по байтам IP для UDP, по данным для TCP; PASS, если у каждого класса ≤ 1 |
| CT-006 Мода длин | длины данных транспорта под остальными нагрузками, по направлениям (голые ACK не в счёт) | доля самой частой длины и не кратны ли 90 %+ длин одному шагу; PASS, если ниже `max_mode_share` и шага нет |
| CT-007 Периодичность | нагрузки `idle` и `chat`: времена прихода пакетов по корзинам, нормированная автокорреляция | высший пик при ненулевом сдвиге; PASS, если ниже `max_peak` |

Остальные тесты — `NO DATA` с причиной: не реализован или полевой тест (CT-012), которым лаборатория быть не может. Клетки с цензором не учитываются: они измеряют цензор не меньше, чем протокол.

## Пороги

CRTS оставляет пороги профилю проверяемой реализации. Без порога измерение попадает в отчёт, а исход — `NO DATA`: каталог запрещает подставлять правдоподобное значение, и порог — тоже значение.

```toml
[crts]
ct005 = true
ct006 = { max_mode_share = 0.5 }
ct007 = { max_peak = 0.5, bin_ms = 50, max_lag_s = 30 }
```

`scenarios/lab/ostp-crts.toml` запускает нужные для этого нагрузки.
