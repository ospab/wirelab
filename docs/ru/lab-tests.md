# Прогоны

[English](../en/lab-tests.md) · [Документация](../README.md)

`wirelab lab test` гоняет лабораторию без человека. В файле сценария — рецепты, версии для сравнения, профили канала, пресеты цензора и нагрузки. Каждое сочетание рецепт × версия × цензор × канал — **клетка**, и на каждую клетку поднимается свежая лаборатория. В клетке нагрузки идут из клиента, провод записывается, каждый результат сверяется с порогами сценария.

```bash
wirelab lab test scenarios/lab/ostp-e2e.toml
wirelab lab test scenarios/lab/ostp-ab.toml --dry-run          # только список клеток
wirelab lab test scenarios/lab/recipes.toml --only xray        # клетки, в имени которых есть "xray"
wirelab lab test scenarios/lab/smoke.toml --keep               # оставить последнюю лабораторию для панели
wirelab lab test scenarios/lab/smoke.toml --out runs/mine
```

Всё работает на вашей машине: минуты CI не тратятся, повторять можно сколько угодно.

## Исходы

Каждая проверка — **PASS**, **FAIL** или **NO DATA**. NO DATA значит, что измерение не удалось (клиент не подключился, нагрузка ничего не напечатала, не нашлось процесса для замера памяти); ничего вместо него не подставляется. Нагрузка, которой не с чем сравнивать, показывает `-` и своё измерение.

Код выхода: 0, если ничего не провалилось; 1, если провалилась проверка; 3, если клетку не удалось запустить.

## Результат

`runs/lab-<имя>-<время>/` (или `--out`):

| Файл | |
|---|---|
| `report.md` | Таблица (строка на клетку, столбец на нагрузку, какое правило цензора сработало и когда), версии рядом и по каждой клетке все проверки с измеренными значениями. |
| `report.json` | То же для программ. |
| `crts.md`, `crts.json` | Если есть раздел `[crts]`: см. [CRTS](crts.md). |
| `scenario.toml` | Сценарий, как он был запущен. |
| `cells/<n>-<имя>/` | `result.json`, `wire.pcapng` с решениями цензора в комментариях к пакетам, `censor.jsonl`, логи setup и логи рецепта с обоих узлов. |

## Формат сценария

```toml
name = "ostp-e2e"               # для id лаборатории и папки прогона
about = "Одна строка для отчёта."
base = "alpine"                 # переопределить образ рецептов
port = 443                      # порт сервера
blob_mb = 100                   # размер http://target.lab/blob
setup_timeout_s = 60            # оба setup.sh должны выйти с 0 за это время
connect_timeout_s = 30          # первый запрос через туннель за это время
capture = true                  # записывать провод (нужно для CRTS и комментариев цензора)
snaplen = 256                   # байт на пакет: заголовки и SNI из ClientHello
censor = ["off", "ru-tspu.json"]   # пресеты из containers/censor/presets; по умолчанию ["off"]

[[recipe]]                      # один или больше
use = "ostp"                    # имя рецепта
label = "udp"                   # имя в отчёте; по умолчанию имя рецепта
set = { transport = "udp" }     # параметры рецепта

[[variant]]                     # необязательно: версии (или любые наборы параметров) для сравнения
label = "beta.13"
set = { version = "v0.4.7-beta.13" }

[[path]]                        # необязательно; по умолчанию один чистый канал
label = "300M-35ms"
rtt_ms = 35                     # RTT, делится между направлениями
rtt_jitter_ms = 0
loss_pct = 0.01                 # в каждую сторону
duplicate_pct = 0
corrupt_pct = 0
rate_kbit = 300000              # в каждую сторону

[[workload]]                    # одна или больше, по порядку в каждой подходящей клетке
kind = "down"
label = "speed"
paths = ["300M-35ms"]           # только в клетках с этими каналами (также: recipes, censors)
min_mbps = 100

[crts]                          # необязательно: см. crts.md
ct005 = true
ct006 = { max_mode_share = 0.5 }
ct007 = { max_peak = 0.5 }
```

Неизвестные ключи отвергаются: опечатка в пороге — ошибка, а не проверка, которая молча не выполняется.

### Нагрузки

| `kind` | Что делает | Проверки | Поля (по умолчанию) |
|---|---|---|---|
| `down` | Скачивает blob через туннель | размер и sha256 против цели; скорость | `max_s` (300), `min_mbps` |
| `up` | Отдаёт случайные байты через PUT; сервер затем читает их с цели в обход туннеля | sha256 на дальней стороне; скорость | `bytes_mb` (20), `max_s`, `min_mbps` |
| `web` | 40 объектов страницы, параллельно, несколько раундов | все объекты целы; общее время | `rounds` (3), `parallel` (6), `max_s` (120) |
| `stream` | Скачивание с ограничением скорости на заданное время | доля удержанной скорости | `rate_kbit` (4000), `seconds` (30), `min_share` (0.9) |
| `chat` | Мелкие запросы со случайными интервалами около `interval_s` | все получили ответ; p95 задержки | `count` (30), `interval_s` (2), `max_p95_ms` |
| `idle` | Ничего: только собственный трафик туннеля | только замер (CRTS CT-007) | `seconds` (60) |
| `unauth` | Неавторизованные пробы на порт сервера: случайный UDP по 64 и 1200 байт, случайный TCP, HTTP GET | только замер (CRTS CT-005) | |

Поля, общие для всех нагрузок:

| Поле | |
|---|---|
| `label` | Имя столбца; по умолчанию вид нагрузки. Имена уникальны. |
| `paths`, `recipes`, `censors` | Запускать только в подходящих клетках. |
| `max_s` | Наибольшая длительность. |
| `outage = [{ at_s = 3, for_s = 30 }]` | Оборвать канал (100 % потерь в обе стороны) во время нагрузки, затем восстановить. |
| `target_rate_kbit` | Замедлить канал цели в обе стороны: медленный сайт за сервером. |
| `max_server_rss_mb` | Наибольшая допустимая память серверного процесса рецепта, замер каждую секунду. |

## Версии рядом

При двух и более `[[variant]]` в отчёте появляется таблица: каждый рецепт, канал, цензор и нагрузка, главное измерение для каждой версии и разница с первой (+ — лучше, в какую бы сторону ни шло измерение). В варианте можно указать `src` на локальную сборку и сравнить её с релизом.

## Примеры в `scenarios/lab/`

| Файл | |
|---|---|
| `smoke.toml` | Один рецепт, несколько маленьких нагрузок: поднимается ли и передаёт ли данные. |
| `recipes.toml` | Все рецепты, без цензора и с пресетом ТСПУ. |
| `ostp-e2e.toml` | Проверка релиза OSTP: 100 МБ в обе стороны по UDP и TLS, скорость на быстром канале, обрывы на 5 и 30 с посреди скачивания, память сервера при медленном сайте. |
| `ostp-ab.toml` | Две версии OSTP на чистом канале и канале с потерями, с цензором и без. |
| `ostp-crts.toml` | Замеры CRTS для OSTP. |
