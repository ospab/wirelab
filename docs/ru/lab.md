# Лаборатория

[English](../en/lab.md) · [Документация](../README.md)

Лаборатория — четыре контейнера в изолированных сетях. Трафик между клиентом и сервером может идти только через провод, который применяет помехи канала и цензор и записывает всё, что проходит.

```
client 10.77.1.3 ── wire 10.77.1.2 | 10.77.2.2 ── server 10.77.2.3 ── target 10.77.3.10
     net_c                                 net_s                 net_t (выхода наружу нет)
```

| Узел | Роль |
|---|---|
| client | Клиент протокола. До сервера достаёт только через провод. |
| wire | Маршрутизирует между сетями: netem на обоих исходящих интерфейсах, цензор между ними, захват на стороне клиента. |
| server | Сервер протокола. Единственный узел, который видит цель. |
| target | Интернет за сервером: nginx по имени `target.lab`. |

Клиент тоже знает имя `target.lab` — для туннелей, которые маршрутизируют, а не проксируют (WireGuard); без туннеля адрес с клиента недоступен.

## Запуск и остановка

```bash
wirelab lab up [--id default] [--base alpine|debian] [--port 443] [--recipe ИМЯ --set k=v ...] [--blob-mb 20] [--force]
wirelab lab panel [--id default] [--port 7077]
wirelab lab down [--id default]
```

| Параметр | Значение |
|---|---|
| `--id` | Имя лаборатории; её файлы в `lab/<id>/`. |
| `--base` | Образ клиента, сервера и цели: Alpine (musl) или Debian (glibc). |
| `--port` | Порт сервера; в контейнерах — `WL_SERVER_PORT`, адрес сервера — `WL_SERVER_ADDR`. |
| `--recipe`, `--set` | Настроить оба узла по [рецепту](recipes.md). |
| `--blob-mb` | Размер `http://target.lab/blob`. |
| `--force` | Заменить `setup.sh` в папках узлов, написанный не рецептом. |

Все лаборатории используют одни подсети, поэтому одновременно поднята может быть одна; `lab up` называет мешающую и команду, чтобы её остановить.

## Папки

| На хосте | В контейнере | |
|---|---|---|
| `lab/<id>/client/` | `/lab` у клиента | `setup.sh` отсюда выполняется при каждом старте; вывод в `setup.log`. |
| `lab/<id>/server/` | `/lab` у сервера | так же |
| `lab/<id>/shared/` | `/shared` у клиента и сервера | Очищается при `lab up`. Через неё рецепты обмениваются ключами. |
| `lab/<id>/sessions/<unix-время>/` | `/out` у провода | Всё, что записано за этот запуск лаборатории. |

Так как `setup.sh` выполняется при каждом старте, лабораторию можно пересоздать, не настраивая её заново руками.

## Цель

| URL | |
|---|---|
| `http://target.lab/blob`, `/blob.sha256` | Случайные байты (`--blob-mb`) и их sha256. |
| `http://target.lab/obj/1` … `/obj/40` | Объект *i* весит 2000 + 700·*i* байт: ресурсы страницы. |
| `http://target.lab/up/<имя>` | PUT сохраняет загрузку, GET возвращает, DELETE удаляет. |

## Панель

`wirelab lab panel` слушает только 127.0.0.1 и требует токен, который печатает: консоли — это root-оболочки в лаборатории.

- **Консоли** клиента и сервера (xterm.js), обе пишутся в папку сессии.
- **Провод**: пакеты и байты в обе стороны, график за пять минут (скорость в каждую сторону, RTT, решения цензора отметками) и лента пакетов с тем, что прочитали разборщики: TLS ClientHello с SNI и ALPN, ServerHello, ICMP unreachable.
- **RTT** считается пассивно по TCP (сегмент клиента, затем ACK сервера на него). Для UDP-протоколов включите *ping the server every second*; пинги видны на проводе.
- **Помехи**: задержка и джиттер как RTT (делятся между направлениями), потери, дубли, порча, скорость. Показано ровно то, что держит `tc`.
- **Цензор**: выберите пресет, включите или выключите правила и [гипотезы](censor.md#гипотезы), примените. Решения появляются с правилом и источником.
- **Секреты в открытом виде**: метки и значения (UUID и hex — ещё и как байты) ищутся в каждом пакете.
- **Download session archive**: см. ниже.

## Записи сессии

| Файл | |
|---|---|
| `wire.pcap` | Захват на стороне клиента: клиент→сервер как отправлено, сервер→клиент после помех. |
| `censor.jsonl` | Решения цензора, по JSON на строку: время, правило, действие, поток, направление, длина данных, подробности, источник. |
| `censor-preset.json` | Активный пресет с выбранными гипотезами. |
| `wire-changes.log` | Все изменения помех и цензора с командами `tc`. |
| `client-console.log`, `server-console.log` | Сырой вывод консолей. |

## Архив сессии

```bash
wirelab lab export [--id default] [--session latest|<unix-время>] [--out файл.tar.gz]
```

или **Download session archive** в панели. В архиве — папка сессии, описание лаборатории, логи setup, рецепт с итоговыми параметрами и `wire.pcapng`: захват, где каждое решение цензора записано комментарием к пакету, на котором оно принято. В Wireshark фильтр `frame.comment` показывает их списком; решения, не привязанные к пакету, — в *Statistics → Capture File Properties*.
